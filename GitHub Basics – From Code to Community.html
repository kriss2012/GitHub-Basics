01What is Git & GitHub?

Git is a free tool on your computer that tracks changes in your files. It lets you go back to older versions and work with others without overwriting their work.

GitHub is a website that stores Git projects online. It adds teamwork tools: pull requests, issues, automation (Actions), free website hosting (Pages) and more.

GitGitHub
Software on your computerWebsite / cloud service
Works offlineNeeds internet
Tracks versionsShares & collaborates

Key words

Repository
A project folder tracked by Git.
Commit
A saved snapshot of changes.
Branch
A separate line of work.
Remote
The online copy (usually origin).

02Account & Setup

  1. Go to github.com → Sign up → verify email.
  2. Pick a clean username (it appears in your profile link).
  3. Turn on 2FA in Settings → Password and authentication.
  4. Install Git from git-scm.com.
git --version
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
git config --global init.defaultBranch main

Connect safely with SSH (recommended)

ssh-keygen -t ed25519 -C "you@example.com"
cat ~/.ssh/id_ed25519.pub     # copy this output
# GitHub → Settings → SSH and GPG keys → New SSH key → paste
ssh -T git@github.com         # test
Passwords no longer work for Git over HTTPS. Use SSH or a Personal Access Token (Settings → Developer settings).

Build your profile

Add a photo and bio, pin your best repos, and create a repo named exactly like your username with a README.md — it becomes your profile page.

03Creating & Managing Repositories

Click + → New repository. Choose a name, Public or Private, and optionally add README, .gitignore and a license.

Start from your computer

mkdir my-project && cd my-project
git init
echo "# My Project" > README.md
git add .
git commit -m "Initial commit"
git branch -M main
git remote add origin git@github.com:USERNAME/my-project.git
git push -u origin main

04Clone, Fork, Pull, Push

Clone
Download a repo to your computer.
Fork
Your own online copy of someone else's repo.
Pull
Bring new online changes to your computer.
Push
Send your commits online.
# Clone
git clone git@github.com:USERNAME/repo.git
cd repo

# Push your work
git add . && git commit -m "Add feature"
git push

# Pull latest
git pull origin main

Working with a fork

git clone git@github.com:YOU/repo.git
git remote add upstream git@github.com:OWNER/repo.git
git fetch upstream
git merge upstream/main     # keep your fork updated
git push origin main
fetch only downloads changes. pull = fetch + merge.

05Branching & Merging

A branch lets you try ideas without breaking main.

git branch                    # list branches
git switch -c feat/login      # create + move
# ...edit, add, commit...
git push -u origin feat/login
git switch main
git merge feat/login
git branch -d feat/login      # delete after merge

Merge conflicts

A conflict happens when two people change the same lines. Git marks them:

<<<<<<< HEAD
your version
=======
their version
>>>>>>> feat/login
  1. Open the file, keep the correct code, delete the 3 marker lines.
  2. git add file
  3. git commit (or git merge --continue).

Stuck? Cancel with git merge --abort.

Naming tip: feat/name for features, fix/name for bugs.

06Pull Requests (PR)

A PR asks the project to review and merge your branch.

  1. Push your branch.
  2. Click Compare & pull request.
  3. Write a clear title and describe what and why. Link issues with Closes #12.
  4. Wait for checks (Actions) and reviews.
  5. Fix feedback by pushing more commits — the PR updates itself.
  6. Merge: Merge commit, Squash (one clean commit) or Rebase.
## What
Adds login form validation

## Why
Users could submit empty fields

Closes #12

Use Draft PR when work is unfinished.

07Contributions & Open Source

Your first contribution

  1. Find a repo; search issues labelled good first issue or help wanted.
  2. Read README.md, CONTRIBUTING.md and CODE_OF_CONDUCT.md.
  3. Comment on the issue to claim it.
  4. Fork → clone → branch → fix → commit → push.
  5. Open a PR and be polite and patient.

Good habits

  • Small, focused changes.
  • Clear commit messages: fix: handle empty email.
  • Follow the project's style and tests.

Your green contribution graph on your profile shows daily activity. Check the License (MIT, Apache-2.0, GPL) before reusing code.

10Introduction to GitHub Actions

GitHub Actions runs tasks automatically when something happens in your repo — like a push or PR. This is called CI/CD: CI (Continuous Integration) builds and tests code; CD (Continuous Deployment) publishes it.

Workflow
A YAML file in .github/workflows/
Event
The trigger (push, pull_request)
Job
A group of steps on one machine
Step
One command or action
Runner
The machine (ubuntu-latest)
Action
Reusable step, e.g. actions/checkout
Public repos get free Actions minutes. YAML is sensitive to spaces — use 2 spaces, never tabs.

11Creating a Workflow (CI/CD Basics)

Create .github/workflows/hello.yml, commit and push. See it in the Actions tab.

name: Hello Workflow

on:
  push:
    branches: [main]
  pull_request:
  workflow_dispatch:      # manual "Run workflow" button

jobs:
  hello:
    runs-on: ubuntu-latest
    steps:
      - name: Get the code
        uses: actions/checkout@v4

      - name: Say hello
        run: echo "Hello from GitHub Actions!"

      - name: Show files
        run: ls -la

Common triggers

on:
  schedule:
    - cron: "0 3 * * *"     # every day 03:00 UTC
  release:
    types: [published]
  push:
    paths: ["src/**"]       # only when src changes

Multiple jobs & needs

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - run: echo "testing"
  deploy:
    needs: test             # runs only if test passes
    runs-on: ubuntu-latest
    steps:
      - run: echo "deploying"

12Build & Test Workflow

Node.js example

name: CI

on: [push, pull_request]

jobs:
  build-test:
    runs-on: ubuntu-latest
    strategy:
      matrix:
        node: [18, 20]       # test on both versions
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: ${{ matrix.node }}
          cache: npm
      - run: npm ci
      - run: npm run build --if-present
      - run: npm test

Python example

name: Python CI
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"
          cache: pip
      - run: pip install -r requirements.txt
      - run: pytest

Save build output (artifacts)

      - uses: actions/upload-artifact@v4
        with:
          name: build-files
          path: dist/

A green ✅ means passed; red ❌ means failed. Click the run to read the logs.

13Deploy a Static Website with Actions

Host HTML/CSS/JS (or React/Vite builds) free with GitHub Pages.

  1. Put index.html in your repo.
  2. Go to Settings → Pages → Source → GitHub Actions.
  3. Add the workflow below and push.
  4. Your site: https://USERNAME.github.io/REPO/

Plain HTML site

name: Deploy Site

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  deploy:
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - uses: actions/checkout@v4
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: .             # folder to publish
      - id: deployment
        uses: actions/deploy-pages@v4

Vite / React site (build first)

    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npm run build
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist
      - id: deployment
        uses: actions/deploy-pages@v4
Blank page or missing CSS? Set the base path. In Vite: base: "/REPO/" in vite.config.js.

14Environments & Secrets

Secrets store private values (API keys, tokens) encrypted. Variables store non-private settings.

Add: Settings → Secrets and variables → Actions → New repository secret.

steps:
  - name: Use a secret
    env:
      API_KEY: ${{ secrets.API_KEY }}
      MODE: ${{ vars.APP_MODE }}
    run: ./deploy.sh      # reads $API_KEY safely
Never echo a secret. GitHub hides them as *** in logs, but don't rely on it. Secrets are not passed to workflows from forks.

Environments

Create in Settings → Environments (e.g. staging, production). Add secrets per environment, required reviewers (manual approval) and branch limits.

jobs:
  deploy-prod:
    runs-on: ubuntu-latest
    environment: production   # waits for approval if set
    steps:
      - run: echo "Deploying with ${{ secrets.PROD_TOKEN != '' }}"

Built-in values

ExpressionMeaning
${{ github.actor }}User who triggered it
${{ github.ref_name }}Branch / tag name
${{ github.sha }}Commit ID
${{ secrets.GITHUB_TOKEN }}Auto token for the repo

15Automating Deployments

Full pipeline: push → test → build → deploy. Deploy only if tests pass.

name: CI/CD

on:
  push:
    branches: [main]

permissions:
  contents: read
  pages: write
  id-token: write

jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci
      - run: npm test

  build:
    needs: test
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with: { node-version: 20, cache: npm }
      - run: npm ci && npm run build
      - uses: actions/upload-pages-artifact@v3
        with: { path: dist }

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.d.outputs.page_url }}
    steps:
      - id: d
        uses: actions/deploy-pages@v4

More automation ideas

  • Dependabot – auto PRs for outdated packages: add .github/dependabot.yml.
  • Auto-label PRs and welcome new contributors.
  • Scheduled jobs with cron.
  • Release on tag: on: push: tags: ["v*"].
# .github/dependabot.yml
version: 2
updates:
  - package-ecosystem: npm
    directory: "/"
    schedule:
      interval: weekly

16Errors & How to Fix Them

Tap an error to see the fix.

Git errors

Permission denied (publickey)

GitHub can't find your SSH key.

ssh-add ~/.ssh/id_ed25519
ssh -T git@github.com

Make sure the public key is added in GitHub settings, or switch to HTTPS with a token.

Authentication failed / Password auth removed

Use a Personal Access Token as the password, or switch to SSH:

git remote set-url origin git@github.com:USER/REPO.git
fatal: not a git repository

You're in the wrong folder. cd into your project or run git init.

failed to push some refs / rejected (non-fast-forward)

The online repo has commits you don't have.

git pull --rebase origin main
git push
remote origin already exists
git remote -v
git remote set-url origin NEW_URL
Merge conflict

Edit the file, remove <<<<<<< markers, then:

git add .
git commit -m "Resolve conflict"
Please tell me who you are
git config --global user.name "Your Name"
git config --global user.email "you@example.com"
Committed to wrong branch / wrong message
git commit --amend -m "Correct message"   # last commit only
git reset --soft HEAD~1                     # undo commit, keep files
Accidentally committed a secret or big file

Revoke the secret immediately and make a new one. Then remove the file:

git rm --cached .env
echo ".env" >> .gitignore
git commit -m "Remove .env"
File exceeds 100 MB limit

Use Git LFS (git lfs track "*.zip") or don't commit large files.

Detached HEAD
git switch main

To keep work done there: git switch -c new-branch

GitHub Actions errors

Workflow doesn't appear / doesn't run
  • File must be in .github/workflows/ exactly, ending in .yml or .yaml.
  • Check on: branch names match yours (main vs master).
  • Actions must be enabled in Settings → Actions.
Invalid workflow file / YAML syntax error

Fix indentation (spaces only). Quote values with colons or ${{ }} in tricky places. Use an editor with YAML highlighting.

Process completed with exit code 1

A command failed. Open the failing step and read the lines above the red error. Run the same command on your computer to reproduce.

npm ci fails: package-lock.json not found

Commit package-lock.json, or use npm install.

Resource not accessible by integration (403)

Give the workflow permission:

permissions:
  contents: write     # or pages: write, pull-requests: write

Also check Settings → Actions → General → Workflow permissions.

Pages deploy: "Get Pages site failed" / not enabled

Go to Settings → Pages and set Source to GitHub Actions. Make sure the repo is public (or your plan supports private Pages).

Site shows 404 or blank page after deploy
  • Need index.html in the published folder.
  • Fix asset paths: use relative paths (./style.css) or set base.
  • Wait 1–2 minutes and hard-refresh.
Secret is empty in the workflow

Check exact name spelling (case-sensitive), that it's in the right scope (repo vs environment), and that the run isn't from a fork.

Action not found / Unable to resolve action

Check spelling and version: actions/checkout@v4. Pin to an existing tag.

Job waiting for approval

Your environment has required reviewers. A reviewer must click Review deployments → Approve.

Debug tip: add a step run: pwd && ls -la to see where files are. Use Re-run jobs → Enable debug logging for more details.
